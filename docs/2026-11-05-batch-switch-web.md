# 用 Python 构建 H3C / 飞塔批量命令 Web 管理台

设备巡检和配置变更经常需要在多台设备上重复执行命令。我把原有的 SSH 批量脚本加上了 Web 页面：按设备类型筛选、勾选目标、输入命令，再查看每台设备的执行结果。H3C 交换机和飞塔 FortiGate 防火墙分别读取自己的 IP 文件，使用对应的 Netmiko 驱动。

本文记录本机部署、页面使用和常见问题。工具已通过 **43 项离线模拟测试**，这不等于所有设备型号、固件和现场业务都已验证。正式变更仍须备份配置、准备带外访问和回退方案，先在单台设备验证。

源码目录：https://github.com/yanghsuo/pythonProject-MacOS/tree/master/GALBOT/6.batch_switch_cmd

源码的可访问范围取决于仓库权限；如果仓库是私有的，需要登录有访问权限的 GitHub 账号才能查看或克隆。本文公开介绍使用方法，不改变仓库可见性。

## 一、运行在哪里，能做什么

管理台运行在具备设备管理网络访问能力的电脑或受控服务器上。Flask 提供页面和任务接口，Netmiko 通过 SSH 执行命令；GitHub Pages 只托管本文这样的静态文档，不能运行 Flask 或向设备建立 SSH 连接。

主要能力包括设备搜索和分类、查询及配置命令、并发执行、仅预览、逐台结果和历史任务。当前本地双文件模式面向 H3C 和 FortiGate；不同类型设备必须分开下发同一组命令。

它不是配置事务系统，也不提供自动回滚、交互式确认回答或完整的设备兼容性保证。页面显示成功，表示执行过程中未发现已覆盖的常见 CLI 错误，业务状态还要另外核验。

## 二、获取代码并创建独立环境

使用 Python 3.9 及以上，建议使用仍受维护的 Python 版本。以下命令适用于 macOS 或 Linux；克隆私有仓库前先完成 GitHub 认证。

```bash
git clone https://github.com/yanghsuo/pythonProject-MacOS.git
cd pythonProject-MacOS/GALBOT/6.batch_switch_cmd
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
```

已经有代码时，直接进入工具目录即可。依赖文件包含 Flask、Netmiko，以及用于服务器部署的 Gunicorn。独立虚拟环境能避免与其他网络运维脚本的依赖混用。

启动前，确认电脑到设备管理 IP 有路由，SSH 服务和管理访问策略允许连接，账号具有相应命令权限。仅预览不连接设备，因此无法替代这些检查。

## 三、准备两个实际 IP 文件

默认读取 **app.py 所在目录**的两个文件，而不是终端启动目录：

- `ip_h3c.txt`：H3C 交换机，使用 `hp_comware` 驱动。
- `ip_fortigate.txt`：飞塔防火墙，使用 `fortinet` 驱动。

仓库提供的是带 `.example` 后缀的格式示例。首次使用可以复制为实际文件；`cp -n` 用于避免覆盖已有列表：

```bash
cp -n ip_h3c.txt.example ip_h3c.txt
cp -n ip_fortigate.txt.example ip_fortigate.txt
chmod 600 ip_h3c.txt ip_fortigate.txt
```

随后编辑两个 `.txt` 文件，将示例地址替换为真实管理 IP。下面仅说明格式，使用的是文档保留地址，不可当作你的设备直接执行。

H3C 文件：

```text
# 每行一个 H3C 管理 IP
192.0.2.10
192.0.2.11
```

飞塔文件：

```text
# 每行一个 FortiGate 管理 IP
198.51.100.20
```

支持空行、以 `#` 或 `//` 开头的注释和小网段。同一文件内会去重，两个文件不能包含同一 IP；总计最多 4096 个地址。只有一种默认文件存在时可以加载该类型并提示另一种缺失；两个都缺失会报错。

已有文件在其他目录时，用绝对路径指定，不必移动：

```bash
export H3C_IP_FILE="$HOME/network-lists/ip_h3c.txt"
export FORTIGATE_IP_FILE="$HOME/network-lists/ip_fortigate.txt"
```

这些目录和文件须实际存在。显式指定的文件不存在时会报错。环境变量中的相对路径按启动工作目录解析，默认路径则始终相对于 app.py。

增删设备请修改 IP 文件，点击页面“刷新列表”即可，无需重启。设备类型由来源文件决定；名称、端口和专用账号可以在页面编辑，不会修改源 IP 文件。

## 四、启动页面和配置登录凭据

原服务器版支持 `IP_LIST_FILE` 单文件模式。进入本机双文件模式前，清除旧变量：

```bash
unset IP_LIST_FILE
.venv/bin/python app.py
```

浏览器打开：`http://127.0.0.1:8765`。默认只监听本机，未设置 Web 管理凭据时仅允许本机访问。

页面的“默认用户名”和“网络设备密码”用于设备 SSH 登录，和可选的 Web 管理登录是两套凭据。可以在页面临时填写，也可以分别为两类设备设置环境变量后再启动：

```bash
export H3C_USERNAME='替换为交换机账号'
export H3C_PASSWORD='替换为交换机密码'
export FORTIGATE_USERNAME='替换为飞塔账号'
export FORTIGATE_PASSWORD='替换为飞塔密码'
.venv/bin/python app.py
```

上述值全是占位符。真实密码不要写进文章、截图、公开文件或 shell 历史；页面临时输入通常更适合单次操作。两类设备确实共用凭据时，可以使用 `DEVICE_USERNAME` 和 `DEVICE_PASSWORD`。

设备文件内账号和页面保存的专用账号优先于任务默认账号；厂商用户名环境变量也会作为对应设备的默认值。密码尝试顺序为设备专用密码、页面临时密码、对应厂商密码、共用密码。H3C 厂商密码不会拿去尝试飞塔，反之亦然；只有 SSH 登录认证失败才会尝试下一套密码，执行阶段失败不会自动换密码重发。

## 五、先预览查询，再逐步扩大范围

推荐按以下顺序使用：

- 选择“H3C 交换机”或“飞塔防火墙”，再勾选目标。切换类型会清空已有勾选。
- 每行输入一条命令。顺序和重复次数都会保留，不需要删除配置块中重复的退出命令。
- 勾选“仅预览”，核对设备、命令和模式。预览不会建立 SSH 连接，也不会检查设备命令语法、权限或连通性。
- 在批准的范围内，先取消预览并对单台执行。实际下发会再次要求确认。
- 核对输出和业务状态后，再扩大设备数量和并发数。

H3C 查询可以使用：

```text
display version
display clock
```

飞塔查询可以使用：

```text
get system status
get system performance status
```

查询保持默认执行模式，不勾选“配置模式”或“下发后保存”。实际 SSH 连接时，驱动可能为读取输出临时调整控制台分页；飞塔驱动会在断开时尝试恢复，启用虚拟域时还可能需要全局配置权限。因此“查询命令”也不等于整个连接过程完全没有设备侧操作。

每个任务最多 500 条命令、并发数 1–20、超时 5–600 秒。最多两个任务同时运行，正在执行的设备不能被另一个任务重复选中。并发不是越高越好，应考虑设备负载、管理链路和认证系统限速。

## 六、H3C 与飞塔的配置方式不同

### H3C：配置模式自动进入 system-view

修改 H3C 配置时勾选“配置模式”，脚本负责进入配置视图，不需要在输入框额外添加 `system-view`。需要写入启动配置时，再勾选“下发后保存”。

下面的命令会修改设备名称，仅用来说明输入方式，应先在测试设备验证：

```text
sysname EXAMPLE-SW
```

涉及接口视图时，按实际型号填写接口名称并保留必要的 `quit`。脚本不是配置差异计算工具，应提前确认命令适用于目标型号和当前状态。

### FortiGate：输入完整 FortiOS 命令块

飞塔需要显式包含 `config`、按需使用的 `edit`、`next` 和 `end` 等上下文；配置模式下最后一条命令必须是 `end`。以下示例同样会修改设备名称：

```text
config system global
set hostname EXAMPLE-FGT
end
```

飞塔不使用交换机通用保存命令，页面会禁用“下发后保存”。常见自动保存模式在 `next` / `end` 时使配置生效；如果设备使用 manual、revert 等保存模式，应按实际 FortiOS 设置另外处理。工具不会自动更改保存模式或追加保存命令。

启用 VDOM（虚拟域）时，明确指定所需的 global 或虚拟域上下文，使用具有对应权限的账号，并完整退出嵌套配置。驱动能适配视图变化后的提示符，但不能代替正确的配置块。

H3C 与飞塔混选时，页面禁用下发按钮，后端也会拒绝。不要通过调整默认厂商来绕过来源文件决定的设备类型。

## 七、结果、失败和重发的边界

任务结果包含每台设备的命令输出、成功或失败状态、错误原因和耗时。“最近任务”可以找回历史结果；关闭网页不会停止已经提交的任务，但退出程序或重启服务会中断任务，重启后不会自动重发。

识别到常见 CLI 错误时，脚本停止该设备后续命令，保留此前收到的输出，其他设备继续。例如飞塔的负数 `Return code` 会被识别为失败。工具不会自动补 `end`、回滚已生效配置或保证识别所有型号的错误格式。

超时也不能证明设备没有执行命令：可能是命令已生效，但输出或提示符未及时返回。失败后先核对设备实际配置，再决定重发哪些命令，避免把已成功的部分再次执行。交互式重启、手工确认、固件升级等操作不适合直接当作普通批量命令发送。

Web 历史默认位于工具目录 `output/jobs/`，名称、端口和专用凭据等附加信息保存在 `devices.json`。页面临时密码不会作为任务密码字段持久化；但命令正文和设备输出仍可能包含敏感配置，应保护这些文件。

## 八、“没有匹配的设备”怎么排查

先看页面顶部的错误提示和设备列表的“来源”路径，再检查筛选条件。这里曾遇到的直接原因是把 IP 填进了 `.txt.example`，而程序只读取 `.txt`：

- 正确文件名是 `ip_h3c.txt` 和 `ip_fortigate.txt`，不能继续带 `.example` 后缀。
- 默认文件必须与 app.py 同目录；其他位置用 `H3C_IP_FILE`、`FORTIGATE_IP_FILE` 指定。
- 两个文件都缺失、显式路径错误、非法 IP 或跨类型重复 IP，会使加载失败。
- 清空搜索内容，确认当前设备类型与文件内容一致。
- 修改文件后点击“刷新列表”。若顶部仍保留旧错误，可刷新整个网页。

文件正确但实际下发失败时，分别检查路由、SSH 端口、账号密码、管理访问策略、VDOM 权限和命令模式。错误信息包含设备上下文，分享排障截图前应脱敏。

## 九、命令行、服务器和文件保护

原批量脚本仍可单独使用，先预览：

```bash
.venv/bin/python batch_cmd.py --devices ip_h3c.txt --vendor h3c --cmd 'display version' --dry-run
.venv/bin/python batch_cmd.py --devices ip_fortigate.txt --vendor fortigate --cmd 'get system status' --dry-run
```

去掉 `--dry-run` 才会实际连接。飞塔配置使用 `--config`，提供完整命令块，不加 `--save`。页面与命令行都应该在具备网络授权的环境执行。

如果仍部署到 Linux 服务器，显式设置 `IP_LIST_FILE` 可以保留旧单文件模式；该模式下厂商由设备附加信息或默认厂商指定，不再按两个文件分类。仓库的 `switch-web.service` 和 `server.env.example` 是服务器部署模板，需要按实际安装位置修改路径。

生产运行使用 Gunicorn **单工作进程**，任务状态和设备互斥保存在进程内，不能使用多实例、多 worker 或自动重载：

```bash
.venv/bin/gunicorn --bind 127.0.0.1:8765 --workers 1 --threads 8 --timeout 120 app:app
```

远程访问前同时设置 `WEB_USERNAME` 和 `WEB_PASSWORD`。通过 SSH 隧道或 HTTPS 保护传输，不把带设备凭据的页面直接公开成明文 HTTP 服务。只有前方确实是可信 HTTPS 反向代理时才设置 `WEB_TRUST_PROXY=1`，后端保持回环监听。

本工具的 `.gitignore` 排除了真实 IP 文件、`devices.json`、环境文件、虚拟环境和 `output/`。公开示例只保留文档地址；不要使用强制添加把真实清单和凭据上传，也不要以为忽略规则能撤回已经进入 Git 历史的敏感数据。

## 十、验证与后续维护

在工具目录运行离线测试：

```bash
.venv/bin/python -m unittest discover -s tests -v
```

本次 **43 项测试通过**，使用临时文件和模拟 SSH，覆盖双文件加载、设备类型、凭据隔离、混选拒绝、命令顺序、失败停止、飞塔配置处理、接口访问校验和历史恢复。没有据此宣称真实设备或全部固件已完成验收。

升级代码或依赖后，先重跑测试，再以少量查询命令验证单台设备。配置变更另外安排批准的窗口、备份、带外连接、回退步骤和业务验收；预览与自动化可以帮助减少重复操作，但不能替代这些管理要求。
